# Play mode: building sprites and draw rules

Data: `data/play/buildings.json` (generated by `tools/play_buildings.py`, re-run after edits there).
Sprite refs are `{file, atlas index}` of `extracted/sprites/<file>/atlas.json` (index counts the 200 system images).
Evidence tags: **exe** = read from Zeus.exe (type table `0x005F6368`, decompile), **eZeus** = from refs/eZeus (facts only),
**seen** = verified by compositing PNGs, **guess** = inferred.

## 1. How the original assigns art (exe)
Type table row: `image_group = collection*512 + group id` (collection 4 Zeus_General, 5 Zeus_Terrain, 52 Poseidon_Loaded) and
`image_offset` into that group. `buildings.json` entries without a note come straight from it (group name in `"group"`).
Corrections to `tools/viewer_sprites.py`: hedge_maze = `SPR_B_REC_AREA2[2]` and topiary = Poseidon `SPR_REC8` (swapped there);
elite vacant lot = `SPR_B_ELITE_HOUSE0A` (the table row is a placeholder).

## 2. Placement (anchor, multi-tile)
- Sim anchor = min corner tile (x, y). Tile top-left pixel `P = ((x-y)*30, (x+y)*15)` (diamond 58x30).
- An image of an n-tile object (width 60n-2, base diamond = its bottom 30n rows): `left = P.x - 30(n-1)`, `top = P.y + 30n - image_h`
  (bottom of the image = bottom vertex of the footprint). exe: draw point shifts by (+30(n-1), -15(n-1)) from the left tile
  (rendering.md 11.2). Use `img_tiles` (iso size) for n, not the sim footprint: e.g. storehouse footprint 3 is 1x1 images,
  elite house 4x4 is four 2x2 images.
- Elevation: `y -= 30*altitude` (terrain doc). Draw order: docs/play/draw-order.md (each picture at its footprint's
  left-corner cell; walkers after the objects of their cell, or 2 / 4 rows later).

## 3. Animations (exe, seen)
- Base image `B` with `anim_frames N > 0`: frames are atlas images `B+1 .. B+N` (same group). Each frame is drawn on top of the base at
  `base_top_left + (B.anchor_x, B.anchor_y)` (can be negative); exe: `x + anchor_x`, `y + anchor_y - base_h + 30(k+1)`. Verified for
  timber mill, college, tax office etc. (`anim.dx/dy`).
- Frame counter runs 1..N and wraps (exe: back-and-forth only when a flag is set; never seen). Frame 0 = base alone.
- When it plays (exe, read 2026-10-28; bug 51). Three steps:
  1. `animation_frame_step` `0x00413380`: no frame (base alone) when the type needs labour (model value 5 != 0) and
     `workers < 1`; types needing no labour (spring, stone circle, baths, bird bath, water park, ...) always animate.
     Stadium/podium/theatre (0x50..0x52) also need `venue_shows > 0`. Agora vendors: only with `vendor_order_active`.
     Dock/trade types 0x0F..0x18, 0x7F, 0x94..0x98 (except 0x16/0x17/0x97/0x98) play 1/4 of a cycle (counter +0xEC); not ported.
  2. `city_draw` `0x00459BF5`: draws via `animation_draw` only if the step returned a frame >= 1 (sculpture studio: also
     when staffed and `workshop_lacks_input` `0x00485310`).
  3. `animation_draw` `0x0045D140` -> `0x0044EAB0` (stall test on the stock `Building+0x3C`): staffed but stalled ->
     **an idle worker figure is drawn instead of the work animation** (the press/beam etc. stop). Stalled when:
     winery 0x35, olive press 0x36: stock < 100; sculpture studio 0x37: < 400; mint 0x30, foundry 0x32, timber mill 0x33,
     horse ranch 0x85, armory 0x87: stock == 0 (gatherers: the gathered stock waiting for a cart). No other condition:
     output full or production progress do not matter. Other types in that switch (lodges, schools, refinery 0xD3,
     chariot workshop, corral, ...) always use the normal animation. (Goat farm 0x2A draws `0x223C` instead when the
     global byte `0x00777285` is set: unknown flag, not ported.)
- Idle figure (exe): SprAmbient packed group `0x204A` (atlas group 73, 12 frames x 8 dirs), or `0x2049` (group 72,
  20 frames) when `grid_random[tile] & 1`; sprite = first + frame*8 + dir; frame advances on the image's speed timer
  (20*speed ms: 120 / 160). Per type `(dx, dy, dir)`: mint (35,11,0), foundry (10,34,2), timber mill (4,36,3), winery (30,2,2),
  olive press (0,28,2), sculpture studio (-5,31,3), horse ranch (0,48,3), armory (3,36,1). Placement (`0x0044DDE0`):
  top-left = (base_left + (base_w+1)//2 + dx - ax, base_bottom - 15*(n+1) + dy - ay) (the exe's draw point, n = picture
  tiles; mirrored buildings use other dx, not ported). Oracle 10-28 (re/oracle/scenarios/overlays.txt): winery, olive
  press, sculpture studio and timber mill idle figures exact at that y in every shot; ours drew them 15 px low
  (base_bottom - 30) until then. The 3x3 horse ranch's idle figure was not seen (h - 60 unverified).
- Ours: the sim computes the rule (`sim/systems/economy.anim_state`: "work" / "idle" / null), the export sends it as
  `b.anim`, scene.js plays the work frames for "work" and draws `buildings.json` `idle` for "idle". Older snapshots without
  `anim` fall back to "staffed = work".
- Speed: raw record byte 58 (`anim.speed`), advance every `20*speed` ms of wall clock (`anim.ms_per_frame`, 100 ms typical;
  `null` = speed 0 = every redraw: use 100 ms). Wall clock, not sim ticks (exe `0x00413330`; unit of the timer is an assumption).
- 40 of the entries have `anim`. Colleges etc. frames show the people moving; the guardpost frames include a flag box (company number).

## 4. Houses (exe, seen)
- Common: `levels[i].variants` (two images, 118x60+, 2x2) for sim level i = 0..6 (Hut..Townhouse); pick `variants[tile_random & 1]`, fixed per tile.
  `vacant` (`SPR_B_FORSALE`) when the house has no people. Poseidon game: levels 2..6 use `poseidon_levels` (same slots, redrawn).
- Elite (sim levels 7..12 = vacant lot, devolved, Residence, Mansion, Manor, Estate): 4x4 drawn as four 2x2 images from the level's
  5-image group (`first + n`): quadrant (0,0) -> n=3, (2,0) -> 4, (0,2) -> `tile_random&1` (0 or 1; this is the actual house), (2,2) -> 2.
  Each quadrant is placed as a 2x2 object at (x+dx, y+dy). Composite looks right (seen). Horse overlays (SPR_ELITE_HOUSE_CHARIOTS) not mapped.
  `Zeus_Terrain SPR_ELITE_OVERLAY` (238x125) is the build-mode/ground footprint, not drawn for finished houses (guess).

## 5. Roads (exe tables decoded; see `road` in buildings.json)
Per road tile choose the **kind** by tile desirability `d` (signed byte): `d<0` rutted (SPR_RUTTED_ROAD, 49 imgs), `0..15` dirt
(SPR_ROADS, 18), `16..29` paved (SPR_PAVED_ROADS, 49), `>=30` plaza (Zeus_General SPR_PLAZA_1X1, 7 imgs, `random%7`). Thresholds from exe
(`0x004A0450`); which 49-image group is rutted vs paved is inferred (medium). Re-evaluated when a neighbour road changes or desirability changes.
Then match the 8 neighbours N,NE,E,SE,S,SW,W,NW = (x,y-1),(x+1,y-1),(x+1,y),(x+1,y+1),(x,y+1),(x-1,y+1),(x-1,y),(x-1,y-1);
neighbour counts as road if flag `0x40` (or `0x08000000`). First matching row of the table wins, image = kind.first + offset.
Dirt table (N,E,S,W only; `1` road, `0` not):

| N E S W | offset | shape |
|---|---|---|
| 1111 | 17 | cross |
| 1110 / 0111 / 1011 / 1101 | 13 / 14 / 15 / 16 | T (missing W / N / E / S) |
| 1100 / 0110 / 0011 / 1001 | 4 / 5 / 6 / 7 | corners N+E, E+S, S+W, N+W |
| 1010 / 0101 | 0 / 1 | straight N-S / E-W |
| 1000 / 0100 / 0010 / 0001 | 8 / 9 / 10 / 11 | dead ends N / E / S / W |
| 0000 | 12 | isolated |

The 49-image kinds use the 48-row table (adds diagonals, e.g. all 8 neighbours = offset 48; offsets 18..47 variants with
corner/diagonal cues); rows are in `road.tab48`. Screen: N = top-right neighbour, S = bottom-left, E = bottom-right, W = top-left.
eZeus's ids agree with this layout for 0..17. Roadblock = `SPR_B_ROADBLOCK` over the road tile. Agora road = `SPR_AGORA_ROAD` (3 variants).
Bridge: see section 9 (unverified). Avenue, boulevard: exe rule, docs/logic/avenues.md "Pictures" (the sim exports
the picture per tile in terrain.json `avenues`; road tiles flat in the terrain layer, side strips as objects).

## 6. Farms, orchards (exe, seen)
- Farm: 3x3 base `SPR_B_FARM` (178x114) always; crops drawn on top as 5 patches (58x30) with offsets (dx,dy) = (-2,0),(-1,1),(0,2),(1,1),(2,0),
  drawn in order 0,4,1,3,2. Patch top-left = `base_top_left + (60 + 30dx, 55 + 15dy - (h-30))` (seen). Stage: `p = min(growth%,100)//4`; each patch in
  order 0..4 takes `min(5,p)` then `p -= 5`; image = crop group `first + stage` (wheat 510.., carrot 516.., onion 522..; 6 stages).
  Fully harvested = stage 0 everywhere. growth% = sim growth (exe: goods_0*100/0x780).
- Orchard tree (olive 497.., grapevine 503.., fruit tree Poseidon 1000..): `min(5, growth%//20)`; ripe = 5.

## 7. Storage (exe)
- Storehouse (sim 3x3): root at (0,0) = `SPR_B_SHOUSE` image (1x1 pavilion); each of the other 8 tiles is a bay: `SPR_B_SBAY_EMPTY` or goods image.
  Trading post (4x4): root `SPR_B_TPOST`, 15 bays. Bay image: `goods_first[res] + band`, band 0 (<200), 1 (<300), 2 (<400), 3 (=400); sculpture single image.
  `bay_images` table in the JSON (keys = resource zeus ids; fruit/black marble/orichalc in Poseidon_Loaded SPR_SH_*). Horses: images blank.
  The sim must expose per-bay good + amount (bays fill smallest-first per exe; bay order along the footprint row-major).
- Granary: base + 16 idle frames (anim at (125,130)); food piles in the 8 roof openings, drawn by `0x004574C0` (called from the
  city draw pass for type 0x39 at the anchor tile, staffed or not) (exe; positions seen):
  - Foods in ascending zeus id (1 urchin .. 7 wheat, 8 fruit; exe walks g_city_food_list 0x010DFDAC, built ascending). Stock = `+0x56 + 2*id`.
  - Piles per food: `n = 1` if stock <= 400, else `stock // 400` (exe loop 0..0xE10 step 400, minus one when not a multiple of 400).
    If the granary is full (free space `+0x56` == 0) and the total < 8, the food with the largest `stock % 400` (first on ties) gets +1.
    (More than 8 piles is possible in the exe, e.g. 2900 wheat + 2 small foods, and reads past the slot table; we stop at 8.)
  - Piles take slots 0..7 in that order. Slot offsets (from the cell point): (57,-49) (77,-56) (97,-63) = back row of 3 openings,
    (51,-32) (71,-39) (91,-46) (111,-53) (131,-60) = front row of 5. Per-food nudge added: 1 (3,0), 2 (0,0), 3 (3,1), 4 (4,-2),
    5 (0,2), 6 (4,2), 7 (2,0), 8 (5,3).
  - Image: Zeus_General `SPR_GRANARY_GOODS` first + id - 1 (packed group 0x86F; table entry `DAT_012E2CFC + 0x370`); fruit (8):
    Poseidon_Loaded group 46 = `SPR_SMALL_FRUIT_ICON` (999, 17x10; entry `DAT_015479BC + 0x168`).
  - Cell point = draw point of the left tile of the 4x4 = `(base_left, base_top + h - 75)` (exe: sloped_top_draw 0x0045A690 size
    code 3 -> building_top_draw(x + 90, y - 45), which puts a 238-wide image at left = x' - 90, top = y' + 120 - h). seen: piles sit in
    the openings (composite and live play mode). Fill uses capacity 3200 from data/buildings.json (exe free space may also count
    reserved deliveries: hyp).

## 8. Vendors / agora
Agora 6x3: strip of 6 `SPR_AGORA_ROAD` tiles + 3 stalls 2x2 on the stall side (`empty_stall` variants 460..462). A vendor placed on
