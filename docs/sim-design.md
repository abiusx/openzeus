# Sim engine design (v0)

Data-only city-builder engine in Python, built for fast iteration. No graphics. The rules are
taken from docs/logic/ (Zeus) and simplified where exactness doesn't matter (decision 2026-10-27,
the decision log).

## Goals
- A tick loop that runs the sandbox: build, people move in, houses evolve, goods flow, money moves.
- Deterministic: same seed + same commands = same result.
- Drivable three ways: a **script** (timed commands), the **CLI** (one command per call, state in a
  save file, so a player agent can drive it through Bash), and the **Python API**.
- Rules and content in **data** (`data/*.json`), hand-editable.

## Layout
```
sim/            engine package
  data.py       loads data/*.json into catalogs
  world.py      228x228 map: terrain, occupancy, roads; sandbox map loader (.map via tools/mapfile.py)
  model.py      Building, Walker, City dataclasses
  game.py       Game: tick loop, command dispatch, observation, save/load (pickle)
  systems/      one module per subsystem (time, desirability, housing, population, labor,
                walkers, services, production, storage, distribution, finance, sentiment, risk)
  render.py     ASCII map + reports
  __main__.py   CLI
data/           buildings.json, houses.json, resources.json, rules.json (generated by
                tools/build_data.py from extracted/model + a role overlay, then hand-editable)
scripts/        deterministic play scripts
```

## Time
1 tick = one walker step. 1 day (Zeus "cycle") = 51 ticks; 16 days = 1 month; 12 months = 1 year.
Slow systems run on day/month boundaries, like the original's 51-step cycle (simplified: each
system runs once per day, in a fixed order).

Walkers are scheduled individually: each walker sits in `g.queue[tick]` for its next tile step
(`rules.walker_pace` ticks per tile at speed code 6, scaled by role speed), so idle ticks cost
nothing. Nothing teleports: immigrants walk from the map entry, emigrants walk out, gatherers
walk off-road (land BFS) to their resource and back (2026-10-27).

## v0 scope (sandbox)
Roads; common housing (Hut..Townhouse; elite later); water (fountain); food chain (farms →
granary → food vendor → houses); fleece/oil/wine chains; services (maintenance, guard, infirmary,
culture venues, tax collector); desirability (incl. beautification); labor; taxes and wages;
sentiment; migration; fire/collapse risk; crime (simplified).
Stubs for now: religion, trade, military, monsters, elite housing.

## Player interface
Commands (text): `build TYPE X Y`, `road X1 Y1 X2 Y2`, `clear X1 Y1 [X2 Y2]`, `tax N`, `wage N`,
`step N`. Observations: `status` (date, money, population, sentiment, labor, stocks, warnings),
`look [X Y W H]` (ASCII map), `info X Y` (tile/building detail, including why a house can't
evolve), `catalog` (buildable types with size/cost/role).

## Performance (2026-10-27)
Measured on scripts/full.txt (191k ticks): 26.6 s -> 11.8 s, identical results (fingerprint of every
building, walker, the treasury and the rng state). What made the difference:
- Coverage: the buildings in a walker's 5x5 square are cached per tile (`services.window`) instead of
  `numpy.unique` on every step.
- Off-road and road paths: a full BFS tree per start tile is cached (`walkers.land_tree`,
  `roads.tree`) and answers every later search from that door; the tree records the order tiles were
  reached, so ties break exactly as the early-exit BFS did.
- Desirability is recomputed only when buildings/keys/rubble change.
- Caches key on `services.occ_version` (map_version minus tree changes): a cut or regrown tree patches
  the walking caches for its tile (`walkers.tree_changed`) instead of dropping everything.
- Hot-path imports moved to module level; burning buildings listed once per tick.
- Iteration: tests run in parallel processes; `run` saves a checkpoint every game year keyed by
  (code + data hash, seed, map, script lines so far) in .cache/ckpt and resumes from the longest
  unchanged prefix (`--no-cache` to start over). Caches are not pickled (`Game.CACHES`).
Left: about half the time is the 2.1M walker steps themselves (pure Python per-step cost).

PyPy (8.0.1, `pypy3.11`, numpy installed for it): same results bit for bit, but no faster (full 13.9-16.8 s
vs CPython 12-15 s on a loaded machine). Plain loops run 26x faster under its JIT; this code does not,
likely because of numpy (C-API calls are slow under PyPy and stop the JIT) and big generic functions.
Done for it: hot grid reads use flat list copies (`walkers.road_list`/`flags_list`, `_desl`), no
`g.__dict__` access (`Game.sd`). Making PyPy pay off would need numpy out of the core (World grids as
lists). Not pursued further for now.

Batching ticks (e.g. 15 at a time) would not help: the tick loop is event-driven (walkers act only on
the tick they are due; an empty tick costs ~1 us), and a walker already acts once per tile (15 ticks per
tile). The work is one act per tile walked. Where acts go in full.txt (2.1M): carts on a path 24%,
deer wandering 15%, maintenance 12%, immigrants 6%, sheep 5%, buyers 5%, other animals 7%, the rest
services/peddlers/traders. Options that do cut work:
- Express path walkers, tried and reverted (2026-10-27): carts, buyers, immigrants and emigrants
  acted once per path, positions computed on demand (`where`), acts within a tick in walker id order.
  Exact (same fingerprint with it on and off), acts 2.12M -> 1.42M, but no measurable time gain: a
  cart step cost ~1 us. Not worth the rule that every reader must use `where`.
- Animals now follow the original (production.md "Animal movement (RE)"): grazers re-roll a 20..69
  tick timer and move with chance 1/8; the re-rolls until a move are drawn at once (same
  distribution, one act per move). Sheep acts 100k -> 31k. Deer became boar herds of 7 (the original
  has no deer), which walk ~40% of the time: 615k acts, more than the deer.
- The original (time-core.md §9) is brute force: every walker every tick, every daily pass over all
  buildings, desirability rebuilt daily. Copied: typed building lists (`systems/index.py`, per kind
  or key, id order, cached per occ_version): full 15.6 -> 13.5 s, same results.
- `run --stale` (2026-10-27): checkpoints are also indexed by script prefix without the code hash, so
  after a code change a run can continue from the newest state older code produced.

### Round 3 (2026-10-30)
Benchmarks (`python3 tools/state_hash.py full`; `save COPY --months 12` on copies of a save (gods,
scenario events, heroes on) and saves/live-full.pkl), 3 runs each alternating with a worktree of the old HEAD, same
loaded machine: full.txt 22.8 -> 16.1 s, a year of save H 2.45 -> 1.49 s, a year of live-full 2.77 -> 1.58 s.
Equality: `tools/state_hash.py` hashes the whole pickled game state (every building and walker attribute, numpy
grids, the rng state, dict order kept, sets sorted; per-attribute hashes name a difference) and the building+walker
positions. Identical before/after for full.txt (193,392 ticks) and 4 game years of each save copy
(`... --json A.json`, then `tools/state_hash.py diff A.json B.json`). Changes (none alters a result):
- Monster routes (sim/heroes/monsters.py): route2 (mode 2, a whole-map Dijkstra per call, 958 calls in full.txt,
  then the largest single cost) uses flat keys x * N + y (equal costs pop in the same (x, y) order as tuples) and
  keeps the search per start tile and grid, resuming it for the next goal: the pop order does not depend on the goal.
  route (mode 3 BFS) on flat indices. Both checked against the old code on 300 random start/goal/limit/near
  queries each (0 differ).
- sim/fastrand.py: below / below_sum make the same getrandbits calls as CPython's randrange(k) without its three
  Python frames; used only when an import-time check proves it equal on the running interpreter. Boar restlessness
  (_drift, ~5M draws in full.txt) and risk.update.
- Carts: cart_destination counts carts on their way once per search (economy.incoming_by_target) instead of a
  pass over all walkers per storage (save H's top cost).
- labor.allocate: each job's category and priority group looked up once a day (was 12 passes calling spec).
- Daily building loops (economy.produce, services.spawn) ask gods.curse_free once; health.contact keeps the
  plagued / healer lists until a walker is created; military.cache memoizes the last game (a weak-dict lookup per
  step before); walkers.act tests the roles with their own branch with one set lookup; function-level imports out
  of hot paths (walkers._ver, index.of, risk.fire_dispatch, housing.culture, economy._peddle).
- land_path / land_tree: level-by-level BFS (the same FIFO order, no (tile, depth) tuples).
Profile tops now (cProfile, full.txt 38.8 s under the profiler, was 56.6): walkers.act and its per-step callees
(services.apply, schedule, tile_delay, follow), land_path, labor.allocate, _peddle, roads.tree. save H: storage_room
(trade posts' export checks), cart_destination, land_path. Left: the per-step Python cost itself (2.1M acts).

### Live recording memory (2026-10-30)
sim/live.py Runner.compact thins the recording by age (FRAME_TIERS, STATE_TIERS), keeping the first frame /
snapshot of each bucket:
- frames: everything recorded (1 tick apart at speed <= 30) for FINE_KEEP = 300 ticks; then the 15-tick grid for a
  game year (zlib'd after KEEP_RAW = 4000 ticks, as before); then one per 60 ticks (4 tiles' walk; replay shows
  walkers jumping); past 4 years one per 240 ticks;
- building snapshots: all for 4000 ticks (at speed 30 one per 30 ticks: STATE_WALL), then one per 8 days, past 4
  years one per 2 months; terrains: all kept, all but the newest zlib'd.
A kept frame/snapshot whose delta base was dropped loses its delta (replay gets the whole document). The old code
meant to drop off-grid frames past KEEP_RAW but never did (its 200-frame batch test ran after the cursor had caught
up), so at speed 30 every tick's frame stayed. Measured with `python3 tools/live_mem.py COPY.pkl --months 48
--speed S` (headless Runner, game clock for the wall clock; ends with every query over the timeline parsing): save H
copy, 4 game years, speed 30: recording 221 -> 18 MB, process RSS 443 -> 142 MB (peak 493 -> 227); speed 300:
55 -> 12 MB, RSS 182 -> 149 MB. (The unattended city shrinks over these 4 years.)
